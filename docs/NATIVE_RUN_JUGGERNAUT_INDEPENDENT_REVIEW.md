## 分层复验与来源

独立完成 83 项来源、原生事实与预算核对：103 个源文件、66 个编译输入、3 个宿主输入、7 个产物全部匹配清单，清单规范序列化哈希等于冻结 ID；另有 15 个锁定输入和 52 个兼容源码全部匹配。当前 100 个执行/配置锁定文件和上轮 328 个原始文件也匹配。

相对上一冻结仅三个生产文件变化：`NativeBranchContract.cs`、`NativeProcessBudget.ps1`、`run-native-slice.ps1`。编译 C# 只变了前者；原生牌效执行链、采集器和 v39 策略不变。因此复验针对选择检查器、包装器与实际新分支，不机械重跑原生全矩阵。结尾再次核对源码、输入和产物无变化。哈希只证明一致性，实际执行结论还依赖原进程记录、原生动作历史及独立进程重放；适用 [证据信任边界](NATIVE_RUN_EVIDENCE_TRUST_BOUNDARY.md)。

共独立调用生产检查器 **26 次**：

- 15 次原始证据/历史副本重验：6 份本轮实际输出，3 个原反例及合法等价副本，既有首项/非首项选择与失败前缀。预期 11 接受、4 拒绝，实际一致。
- 11 个独立副本：2 个合法接受、9 个错误拒绝。覆盖选择与返回共同改指另一候选、返回对象错配、结果早于决策、缺请求/缺结果、错误根动作、错误索引、重复返回、给无子选择的动作声明 Exhaust。每个都重新封签后调用同一个生产检查器，拒绝原因是业务契约，非文件封签故障。

原实现者的 37 次旧证据重读与 13 个修复控制属于实现验收；本轮没有把这些数量重复算作独立执行。

## R1：选择契约

`NativeBranchContract` 在当前派发时取出该强制动作的 Exhaust 约束，跟踪当前 FromHand 请求、显式决策、结果与返回，校验 root/context、请求 ID、候选索引和实际实例，并在确认动作前要求消费完成。

原来误接受的三项现在分别拒绝：改计划 Exhaust 而不改实际执行、删除显式选择决策、改变选择所属 context。独立测试进一步把决策、结果和返回同时指向另一合法候选，仍被当前动作的 Exhaust 约束拒绝；重复返回被通用选择契约拒绝。合法 null Exhaust 的默认策略答复继续接受，历史 live 非首项选择也通过。

这不扩展到任意卡牌/多重嵌套选择、显式 Exhaust 与隐式单候选的组合；原报告明确未覆盖的范围保持。未发现需要为了当前案例修改这些边界的依据。

## R2：120 秒门与自有进程树

两个入口路径都使用 `Wait-NativeProcessBudget`，不存在完整重放放宽为 300 秒的旧分支。六个真实进程均记录 `processTimeoutSeconds=120`，用时约 24.6–27.7 秒，未触发超时。独立验证 helper 和完整包装器均在参数绑定时拒绝 121 秒，后者未启动进程或创建输出目录。

另用三个层级的非游戏自有进程测试实际终止：3 秒门限在约 **3.070 秒**返回超时，根/子/孙三个 PID 均已退出，各层已落盘前缀保留。正常退出 0 和 7 均原样返回且未误判超时。代码使用单调时钟、50 ms 轮询，超时调用 `Kill(true)`，最多另等 5 秒回收；这不是实时系统的 120.000 秒精确硬中断承诺。

这是进程 API 夹具，**不是一次实际游戏运行达到 120 秒的证据**。首次独立夹具在测试结束后的错误类型捕获处发生 PowerShell 类型解析错误，未取得完整总结；保留其脚本和 PID/前缀资料，修正审查脚本后在新目录完成复验。生产代码未改，两次夹具均未运行游戏。

### 33 HP 并不等于只缺 33 点输出

`late-actions.json`、`causal-records.json` 直接给出后续瓶颈：

1. a620 后进入 turn11：玩家 3HP/0Block/3E，Boss39HP且有 Intangible。手牌是 Burn、两张 Strike、Breakthrough、Bash；没有常规格挡或抽牌牌。
2. 两张 Strike 与 Bash 各只造成 1 点攻击伤害和 1 点额外伤害；a623 后 Boss33HP，玩家只有3Block、余1E。
3. a624 的 Burn 先消耗2Block，敌方第一击消耗剩余1Block、实际扣完玩家3HP，并记录10 overkill。没有必要等到后续连击就已死亡。

所以它同时缺存活与非 Intangible 窗口的输出。将“33÷12”解释成还能再打三次 Juggernaut 不成立：此时没有对应手牌、格挡空间和正常伤害窗口。也不能据此证明该状态绝对无解；本轮未穷举所有动作。更早第6/8/9回合的实际失血为22/23/18，已把66HP耗到3HP；这些是可复查事实，改善此前的策略或牌序是否能赢仍是推断。

## 预算与限制

原登记上限为 8 次原生执行、30 分钟、2 GiB、单次120秒。实际 6 次（probe + 3 对照 + detailed tail + 完整 replay），登记至完成约186.88秒，原生进程累计154.54秒，原工作约1.30GiB。剩余两次未临时扩展使用。原始文件锁不变，没有靠删除失败或原始日志节省额度。本轮独立审查成本另列在 closeout，不回填为原实验开销。

MemorySaveStore、shouldSave/UI false、Steam未初始化、Telemetry0、host faults为空；ProgressWrites/ReplayWrites 是已安装拦截器的命中次数，不是真实用户保存写入。没有启动真实UI/网络或操作其它项目，也没有提交推送。

完整 M1 同构建全量门、真实 BossVictory→Architect→RunVictory、未覆盖复活/隐式选择及预持折扣遗物原价采集仍未完成。本轮通过不关闭这些门。
