# 开发取舍原则

优先调查可复用的项目内成果和现有外部实现，核实许可、归属、固定版本、实际依赖、接口边界及维护成本，再确定需要自研的范围。存在代码不等于当前环境可直接使用，缺少现成功能也不自动意味着重写整个系统。

用有明确问题、预算和停止条件的小规模验证支撑技术选择；记录实际收益、失败与未覆盖项。先验证最小纵向闭环，再扩大集成。把原生执行正确性、仿真覆盖、策略强度和性能分别评价，保留可信原生执行作为依据。

按改动影响选择回归范围，复用完整冻结证据，避免没有新理由地重复大规模运行。保存来源、失败分母及可重放数据，最终里程碑的统一验收门保持。第三方许可、补丁审计、隔离和用户授权边界继续适用。
