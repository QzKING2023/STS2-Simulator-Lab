## 实际采集与检查器绑定

已读实际源码和冻结编译输入。`Program.cs` 从当前原生 Run 的唯一玩家取得 `player`；`NativeMajor.cs:38` 在真实战斗开始观察中直接记录 `NativeIdentity.Ref(player.Creature)`。死亡观察的 Own 条件仍以 `ReferenceEquals` 对照该真实玩家 Creature，并要求其已死亡。这里没有从死亡结果反推玩家，也没有硬编码实例编号或卡名。

`NativeDeathContract.cs:27` 起检查这份独立锚点：引用必须登记为 Creature、不得处于当前敌人名单，同一 Run 的本地玩家不可跨战斗更换，并绑定当前战斗房间。既有 `NativeMajorContract` 同时约束观察所属动作、到达顺序、当前房间和不可变完整确认状态。随后致死、移除能力及阶段变更观察的主体、DamageResult 的 Receiver 全部绑定实际玩家；详细模式还交叉检查原生伤害历史的 Actor 和 Receiver。

这关闭了前轮“多个死亡字段一起指向同一敌人或卡牌即可通过”的根因。独立等价控制把玩家引用统一改成新的符号名称后仍被接受，证明检查器没有依赖样本中的 `i23`。
