## 根因和最小变化

旧检查器只将fatal.subject与fatal.Result.Receiver比较，随后把这个自报主体作为整个死亡链的权威值。旧4个坏副本先由原冻结检查器重新执行，均复现exit0误接受，保存在 `pre-fix.json` 和 `reproduce-11`至`reproduce-14`；原独审文件没有修改。

现有投影没有独立的本地玩家引用，无法只靠旧fatal字段完成身份认证。因此在已有 `major-battle-start` 记录中加入 `player`，直接来自原生 `player.Creature`。该对象已由到达/初次抽牌的原生历史登记，增加引用不提前创建实例、不改变稳定编号；实际三种模式448步重放均证明原route和完整边界保持。此观察属于原生生成链变化，本轮运行了受影响原生病例。

采集契约升级为 `native-player-death/v2`。生产 `NativeDeathContract` 要求：

- 每场战斗开始必须有结构明确的玩家引用，已登记类型为Creature，不在该场敌方名单内；同一run本地玩家不可跨战斗更换。
- 当前战斗的玩家锚点与实际room绑定，结合既有Major生命周期的静止状态、顺序及房间归属门。
- 所有致死、能力移除及阶段setter观察的subject，及致死Result.Receiver，都必须等于这个独立玩家锚点。
- 详细模式额外将同条原生DamageReceivedEntry的Receiver、Actor绑定玩家，保留完整DamageResult、历史cursor和快照检查。

生产没有硬编码i23、i911、卡牌名或种子，没有从fatal.subject反推玩家。改动仅3个文件：`NativeMajor.cs`增加真实玩家观察、`NativeDeathObservation.cs`版本号、`NativeDeathContract.cs`身份门。已有能力移除、阶段迁移、原生调用/补丁审计、静止完整状态及RNG检查未删除。
