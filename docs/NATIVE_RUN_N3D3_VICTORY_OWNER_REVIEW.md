## 2. 修复根因与代码审查

`tools/native-run/NativeMajorContract.cs` 的实际修复符合缺陷根因：

1. 每个合法 `dispatch` 使旧条件锚点、完整快照、root/context、历史游标和清理标志失效。
2. 当前原生 `major-victory-condition` 必须属于正在执行的战斗动作，并绑定真实战斗房间、位置和存活/敌人终态事实；记录不可变完整快照及当前 root/context。
3. 胜利回调要求完整状态与本动作条件锚点相等，且 root/context 一致。历史清除和确认后清场继续绑定同一归属、游标和生命周期顺序。
4. 同一动作可能多次得到真实 `IsCombatEnding == true`，允许更新本动作锚点，不能错误要求条件全局唯一。

关联位置：该文件约 114–120 行（dispatch 清除）、189–197 行（条件与回调）、195/199–200 行（历史清除与清场）。根动作顺序仍由 `NativeTraceContract.cs` 校验；战斗 context 仍绑定实际 act/node/具体房间。没有退回只比较几个字段，也没有要求 minimal/off 拥有 detailed 历史。

与上一冻结相比，仅 `NativeMajorContract.cs` 和 `preparation_repair_controls.py` 两个源文件变化；原生生产观察器、策略、角色和游戏逻辑未变。
