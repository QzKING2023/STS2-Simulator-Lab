# 原生流程证据的信任边界与分层验收

本约定用于 M1 内部控制器和生产检查器，不是公开 Mod API。

## 信任什么

固定哈希的本机游戏程序集、已冻结的 Lab 原生宿主及实际执行进程是业务事实来源。原生任务完成、实例登记、动作派发/确认、RNG 和状态观察提供可关联的记录。宿主必须持续保持无 UI、MemorySaveStore、保存/replay 拦截、Steam/网络隔离和严格补丁审计。

检查器把原始文件当作可能截断、丢失、重复、错序、错配或意外修改的数据，必须验证必需记录、动作/上下文/房间/实例归属、静止快照、生命周期和结果分类。日志封签用于完整性，不是对抗恶意宿主的密码学证明。

**不承诺从任意协同重写的整份日志重建真实游戏规则。** 如果所有业务观察、状态、来源和结果被一致地伪造，仅靠这些文件不能证明游戏执行过。防范这一层需要可信冻结执行、输入/产物锁、新进程重放、生产观察与选定独立规则对照；不能靠不断给检查器复制更多原生牌效来替代这些证据。

## 内部契约的统一范围

重复使用同一套基础操作来绑定动作与上下文、保存不可变完整快照、要求某个所有者的阶段恰好发生一次、验证新实例来自本次操作。原生业务期间允许状态变化；静止点必须绑定已确认边界。实际房间/session/act 是所有者，不能靠清空全局计数来进入下一幕。

独立规则只覆盖明确声明的固定版窄规则，例如 A0 Ancient 入场回复、三个 Tezcatara 初始选项及三个 RNG 消耗。其他业务效果由原生执行，记录完整来源和前后状态；其效果没有独立规则复算时明确说明，不把两份同源数据相等当独立证明。

## 验收顺序与停止门

每轮开始先写明改动范围、受影响依赖、明确验收标准和预期失败/未完成分类；已有证据仅在版本、输入、采集口径和适用契约可核对时复用。里程碑明确要求扩大或全量时按该门执行。

1. 检查器修改默认运行定向生产正负控，以及影响范围内**完整冻结原始证据集**的检查器重验；包括原反例、合法等价副本和失败前缀。这不等于重跑全部原生进程。按根因覆盖缺失、重复、错序、归属、实例和静止状态，全部使用副本。
2. 调用接口变化增加最小集成烟测。原生生成链变化按依赖重跑受影响自然路径和必要夹具，包含完整 RNG 重放。保留所有预登记样本，死亡是实际结果，Unsupported/预算仍属于未完成路径。
3. 公共依赖、采集器或工具链具有全局影响，或者范围无法可靠限定、原始证据缺失、既有数据不满足新契约时，扩大到全量原生回归；不能用不适用的旧证据逃避实际执行。
4. 生命周期契约稳定后，同一个最终构建完成全量原生回归、旧共享组件回归、必要完整性控制、完整 run 和预登记评估。最终 M1 全量门保留，前述各层不能替代它。

每次记录改动范围、选择该重跑范围的理由、覆盖和未覆盖风险，并核对源码、输入、构建、采集器、环境指纹。哈希只证明一致性，不证明进程确实执行、效果正确或记录真实；这些结论还需要原始进程状态、真实调用链、原生事实与重放。

证据记录还需保留采集器版本与配置、采集命令/时点、原始文件位置、生产构建与本次检查器版本、退出码及预期/实际结果。未采集、旧格式无法证明或未运行的部分单列；复用证据不改写原 producerBuildId，也不覆盖历史失败。

定向门通过且没有已证实的契约缺陷后，继续推进真实节点；不为了发现任意可想象的整份日志伪造无限增加案例。发现可复现缺陷则修复其可复用根因，保留失败，重新建立受影响层的证据。

每轮报告自然路径最远 act/node、实际战斗胜利、奖励、跨幕与终局，列出 Unsupported 及原始退出。检查数量、代码行数和控制副本数量是证据规模，不代替流程进度。最终 M1 仍要求正常开局完整默认 Acts 至原生 RunVictory，不能用早死或尾部夹具关闭该门。
