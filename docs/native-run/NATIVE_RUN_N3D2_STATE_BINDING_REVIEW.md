## 两类修复的根因核验

`NativeRewardContract.cs:107` 保存不可变实际 Resume 输入，`:113` 在实际任务未完成时也将外层返回绑定当前已验证阶段。`:305` 的锚点推进仅在该记录通过相关生产门后形成有效后续状态；元数据及外层返回不会自行成为新的业务锚点。三个新增合法提前返回位置全部接受，表明没有错误要求外层一定晚于实际任务完成。

`NativeRewardContract.cs:144`–`:148` 分别连接实际 Resume 输入与奖励生成入口、EventRewards 父入口与空集合。后续取得、集合完成、实际任务完成、父返回与确认仍连接同一状态链。`:84` 的有限 V1 药水取得契约保留其余完整结构；`NativeEventFlowContract.cs:44` 将下一 dispatch 绑定前一不可变确认状态，不能通过下一动作恢复原值掩盖临时篡改。

本轮重新阅读锁定 DLL 的本机研究副本及原生驱动。Dummy V1 的原始 Resume 完成事件、从非空解锁药水池调用一次 NextItem，然后等待 OfferCustom；NextItem 经 NextInt 消耗一次随机状态转换。检查器从输入计算四个状态字和 counter 的下一步，未使用输出差异决定允许字段。另用独立的闭式状态转换计算核对实际入口，得到完全一致的快照，见 `transition-observations.json`。

合法业务变化得到保留：空 EventRewards 入口完整不变；Resume 生成阶段只改变事件完成/选项及玩家 Rewards RNG；实际药水取得改变首个空槽及药水清单；战斗清理 HP71→77 仍通过。原生药水生成/取得继续由游戏方法执行，检查器的有限转换用于验证证据，不替代原生业务。

`NativeEventFlow.cs:26` 等待原始 Resume Task，`:64` 等待外层 Proceed，`:67` 再等待实际 Task；本轮没有改变该执行链。故障/预算样本仍为观察包装控制，保留已发生奖励及 **60确认/61派发**，分别 EngineError/exit1 与 BudgetExceeded/exit3；不将其说成自然引擎异常或天然异步延迟。插入故障后伪称成功的独立包被 `Faulted inner task` 拒绝。
