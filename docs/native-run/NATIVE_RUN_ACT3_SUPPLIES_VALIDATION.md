## 自然补给能力

`NativeThirdShop` 将真实 MerchantRoom 库存接入原生多幕控制器。低生命且有金币时，策略根据公开地图寻找商店；购买始终调用原生 `OnTryPurchaseWrapper(ignoreCost:false)` 并等待实际任务、付款、库存变化和回调。单次 ThirdShop 根动作内最多6次购买，只选择声明范围内的默认拾取遗物、卡牌和药水。每个购买有输入/返回事实、实例和完整前后状态。下一次合法 Travel 负责原生退出。

最终自然样本实际完成**5次购买**：会员卡、受电弓、StoneCracker、爆炸安瓿及 Inflame，合计3遗物、1药水、1永久卡。金额和具体实例以原始 `third-shop-buy-*` 记录为准。库存容量阻止继续购买另一瓶药水；“最多6次”不是必买6次。早期开发样本确有6次购买，其原始记录保留，不与最终样本混计。

会员卡的实际获得使后续所有商品及移除价格减半。检查器据固定原版规则校验完整价格投影变化、原始付款和真实新实例，而非要求价格静止或放任任意价格变化。药水价格复用此前已审计的窄 CalcCost TestMode 分支恢复，检查器校验 xoshiro 状态、单次消耗、原生抖动公式及会员卡折扣。

自然商店尚不提供移除、补货、特殊拾取或替换接口；这些已有独立案例不自动等于本控制器已组合。Courier 及超出当前结果契约的交易显式停止。原生 MerchantRoom.Exit 仍处于其既有 TestMode 历史边界，零售购买统计不在本段等价承诺内；房间、动作、金额及取得事实由独立追加日志保留。未伪造零售历史，也未更改全局 TestMode、保存或平台隔离。

## 新事件与合法策略

实际遇到的两次 Unsupported 均保留。只读核实固定原版实现后，增加两个继承无操作 OnRoomEnter 的密封事件入口：

- HungryForMushrooms：只选择真实 BigMushroom 分支，原生获得遗物并增加20最大/当前生命，同时实际承担首回合少抽2张的代价。生产契约校验本次新登记遗物、原牌组与资源、完整状态/RNG，以及20点变化。FragrantMushroom 分支未覆盖，不默认放行。
- PotionCourier：只选择真实 Ransack，调用原生随机药水生成及 OfferCustom。生产契约要求一个实际完成的奖励子集合、完整父子入口/返回状态，并校验 Rewards RNG 的一次选择；最终获得 HeartOfIron。GrabPotions 分支未覆盖。

策略版本为 `oracle-legal-natural-act3-route/v17-native-survival`。使用当前合法手牌、原生意图及公开地图；不读取未来抽牌或 RNG。新策略包含低生命补给/休息排序、濒死且无可用格挡时使用已有赌徒佳酿、避免对人工制品浪费易伤，以及合法使用已有血液药水和钢铁之心。Hemokinesis 的自伤生存检查前移至击杀估算之前。所有效果仍由原生执行，未改角色、HP、金币、卡牌数值或掉落。

这些是有限启发式。开发策略死亡和10个开发进程全部保留，不能据此声明总体胜率、最优策略或全种子支持。公开地图距离计算使用缓存，未穷举所有路线组合。

## 死亡后最大生命值：发现、修复与边界

开发路线537步和545步都实际死亡，但 v2 数据缺少“致死伤害后、能力清理前降低最大生命值”的同步观察。检查器正确拒绝它们。原生 PaperCutsPower 的 AfterDamageGiven 可在此时调用 LoseMaxHp；原始伤害历史本身不提供具体能力实例的完整因果链。

新增精确 `Creature.MaxHp` setter 的前后观察，仅在本地真实玩家已死亡、当前战斗动作内采集，升级为 `native-player-death/v3`。检查器要求同一玩家、当前动作/房间、成对顺序与完整输入，且返回只能发生声明的 maxHp 变化；其他状态及 RNG 保持绑定。没有删除原来的 fatal、能力移除或确认状态门。

最终545步真实记录 setter `86→84`，537步旧路线重新执行后也采集到原先遗漏的边。三观测模式及冻结重放的1090个完整动作边界一致，新采集还与旧545步原生执行的完整状态/RNG相等。旧537步路线的1074个完整边界在新进程重放中保持。

**旧537/545步 v2 原始数据仍未认证**，没有补造锚点；新认证来自新进程真实执行。此前11份缺玩家身份锚点的 v1 旧证据也继续拒绝。已有符合原先窄契约的 v2 证据仍可读取，不被改称新采集结果。
