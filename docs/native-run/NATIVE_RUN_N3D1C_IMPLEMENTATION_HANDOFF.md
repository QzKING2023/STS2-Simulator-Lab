## 已核实的原生顺序与当前停点

固定程序集的 MerchantEntry.OnTryPurchaseWrapper 先检查库存和付款条件，等待子类 OnTryPurchase；成功后原生选择 RestockAfterPurchase 或 ClearAfterPurchase，**然后**执行 AfterItemPurchased，最后调用 PurchaseCompleted。此顺序已只读核验，下一阶段必须用实际事件证明，不能假定先 Hook 后补货。

当前 MerchantBuy 枚举仅含 MerchantCardEntry/MerchantPotionEntry；成功后若不是原 offered 实例取得、或 entry 仍有库存，会抛出明确 Unsupported，保留真实交易前缀。当前经济契约要求第一次三个药水定价、entry 唯一和固定未补货历史，因此不能直接用于补货 profile。

同一 entry 补货可能持有新模型实例和新价格。定价身份应拆为“计算发生序号 + entry + 商品实例/库存版本”，过期决策要拒绝旧库存版本/价格；不能靠 entry 相同接受旧票据。补货次数、价格重算、Shops RNG 消耗按原生实际调用记录，不硬编码成一笔购买一次随机数。

遗物 OnPickup、卡取得替换、药水拒收/满槽或实际替换可能改变所得对象。每个分支需分别声明 offered、实际取得、被替换、拒收及 modifyingModels 来源；未覆盖的结果继续 Unsupported，不能伪造“取得成功”。
