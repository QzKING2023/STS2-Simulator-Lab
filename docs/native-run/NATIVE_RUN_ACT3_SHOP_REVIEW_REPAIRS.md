## R1：完整退出状态绑定

退出开始现在从不可变当前 Travel 派发快照构造预期完整状态，要求该派发等于此前商店操作完成状态，并绑定实际房间与库存。只应用固定原生出栈变化：node 为本次 Travel 目标、floor 增一、room/rooms 为 null，以及旧库存 Cost getter 在非商店房间恢复原始价格。退出返回只允许 `merchant.closed` 变为 true，其余完整快照保持。

原始价格以本次入店、尚未购买折扣遗物的库存记录作为不可变来源，按每个原生 entry 引用绑定。会员卡购买时产生的折扣及奇数截断不能通过乘二可靠还原；退出比较使用入店原价，185→92→185、37→18→37 等真实变化均保留。没有笼统忽略 merchant、库存或 RNG 字段。

旧采集口径没有单独记录 `_cost`。若入店前已持有覆盖 `ModifyMerchantPrice` 的遗物，检查器明确拒绝认证这种缺原价来源的证据；未来要支持该路径需采集实际原价。当前自然样本入店后才取得会员卡，原价来源充分。此门通过固定版 CLR 方法声明来源判定默认实现，避免把继承默认行为的遗物误当价格修改器。首次修复烟测发现默认方法声明于 AbstractModel 的问题，失败构建与日志保留在 `act3-shop-repair-reader01` 和工作目录 `smoke/normal/`；最终产物使用真实继承元数据比较修正。

## R2：实际模型、类型和商品类别绑定

每个入店商品先核对 entry 的实际登记类型；卡牌、遗物、药水再按对应原生模型命名空间查找已登记的 CLR 具体类型，要求可赋值至正确模型基类，并用固定程序集真实 `ModelDb.GetId(Type)` 核对 model。原生该方法仅从类型元数据生成 category/entry，不构造模型、不调用 ModelDb.Init 或查询 canonical 内容集合。没有从卡名猜类名，也没有新增公开扩展接口。

购买开始再次核对当前 offered；返回把同一 acquired 引用、实际牌组/遗物/槽位新增对象的 model 和类型连起来。既有金额、回调、库存、升级、会员卡折扣及其他状态/RNG 契约保持。

| 边界 | 完整契约 |
| --- | --- |
| 入店库存 | 当前房间/库存、14 个独立 entry、三次原生药水定价、实际登记类别和模型、原价来源 |
| 购买开始/返回 | 当前父动作、顺序唯一、完整上次状态、真实 offered/acquired、实际支付与新对象、精确库存和价格变化 |
