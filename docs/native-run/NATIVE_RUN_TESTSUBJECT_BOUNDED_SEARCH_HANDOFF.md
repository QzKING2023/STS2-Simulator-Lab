# TestSubject 有预算组合决策交接

2026-11-03。依据冻结 `187D81167676164F126029FDA951C3D6A20D49E6BDE05317F886EBA081E21D49` 的[独立复审](NATIVE_RUN_TESTSUBJECT_INDEPENDENT_REVIEW.md)。这是下一实施回合可执行的有界方案，本轮未改运行代码或执行搜索。继续沿用已授权 M1、无 UI/真实存档/Steam 网络/Mod 扩展/提交推送等边界。

## 选择方法及理由

建议先做**原生实际 rollout 的小束搜索**，每个分支从正常开局重放已确认前缀，再执行新的合法动作。暂不为 TestSubject/全部卡另建效果镜像，也不要求 CombatSolver 全覆盖后才能推进 M1。现有输入、选择、状态哈希和失败协议可以复用，但当前 runner 只支持整条严格冻结重放，**“精确前缀结束后切换新决策”及计划停点尚须实现**，不能直接截断 route 文件后把 InvalidAction 改成通过。

现有最终 live 约 27.7 秒、burst612 约 28.9 秒，单份 detailed trace 约 116MB，进程峰值约 1.65–1.69GB。这些是本机两次测量，不是吞吐承诺。暂设单原生 worker，串行构建；先利用已有低成本完整前缀重放，不引入状态克隆、重用死亡进程或全局状态回滚。

搜索模式必须标为 **oracle native rollout**：当前候选只读当前合法动作、手牌、资源、阶段、公开意图和实际选择，但分支评分看到了原生未来执行结果。即使不读取隐藏抽牌堆，基于未来 rollout 挑选动作也不等于玩家可见公平策略。原生执行可信度与策略强度分别报告。

## 固定入口与工作包

1. 保留正常开局至 Boss 入场的 574 动作/1148 完整边界。此次进一步固定已同构建验证的 **burst612 a595 确认边界**：第二次原生 respawn 完成、玩家 67HP、第三形态当前 299HP、玩家 turn5 的 Play 状态。该入口从该策略自己的正常开局连续重放得到，不能把其状态注入 v39，不能拼接 v39 的后续状态哈希。所有 route、子选择、奖励和完整状态/RNG 必须精确复现至 a595。
2. 建立窄内部决策 provider：strict prefix replay → 当前合法动作选择 → 可选真实子选择 → 原生执行 → 确认 → 重新枚举。只在预先声明边界切换一次，记录 prefix 源构建/文件哈希、边界及新策略版本。续接后尚无期望 after hash，必须记录实际值；不能关闭前缀校验。新模式不是 frozen-replay，要独立标注 replay-prefix/live-tail。
3. 请求到达时处理 True Grit：用该次真实 FromHand 的候选 handle 和实例关联做选择；记录计划与实际对象。候选改变、少答、多答、过期、错根均拒绝，保留已经执行的原生前缀。至少一个原生样本让预期对象位于非 0 位置且实际被耗尽。可用明确标注的最小 API 夹具验证这一分支，不能把夹具记作正常通关。
4. 建立计划 horizon 停点：实际动作及任务完成、处于安全 Play/终态后才停，记录不可变完整状态和截止原因。计划到达 horizon 不是 Death、Victory 或意外 BudgetExceeded。沿用 Ongoing/SliceBoundary 时须明确 horizon 合约；达到硬预算但没到计划边界则 BudgetExceeded，输出最后确认前缀。查询异常/选择失败必须收尾，不推定未观察到的状态。
5. 先完成上述接口与正负控，再冻结策略参数及样本清单，开始下面一批搜索。不得边看结果边扩大树或调整权重；若需要改变参数，结束本批并保留全部结果。

## 第一批确定预算

| 约束 | 初始值及含义 |
| --- | --- |
| 首个搜索入口 | burst612 a595；本批只搜索此真实入口 |
| 搜索深度 | 最多 3 个由搜索指定的根动作；实际子选择附着父动作 |
| 每节点候选上限 | 4；不同卡实例、目标、耗尽答案均计为不同候选，重复动作合并，省略项记录 |
| 保留宽度 | 2；一个存活/HP 优先，一个有效伤害进度优先，避免只留高 HP 或只留输出；重复节点不占两席 |
| rollout 范围 | 指定动作前缀后用冻结 v39 规则继续，最多经过 2 次真正的敌方完整回合，返回安全 Play 或真实终态；中途原生抽牌/Hook 照常执行 |
| 候选原生执行 | 最多 4 + 8 + 8 = 20 次，失败、重复、超时也占配额，不补跑以求全绿 |

| Boss 尾部 | 最多 96 根动作、16 个玩家回合、128 个子选择；与进程时间限制取先到者 |
| 整批 | 60 分钟墙钟或新增证据 8GiB 或进程预算用尽，任一先到立即停止新增分支；这是停止上限，不是工期预测 |

候选生成必须事先固定，避免继续人工逐次调常数：包括 EndTurn、当前默认合法首选、一个不同的防御/混合动作、一个不同的攻击/抽牌或 True Grit 答案。最多四个；True Grit 的另一答案也占一个位置，不能额外暗加子分支。具体排序和舍弃规则在开跑前写入配置与哈希。不能先排列初始手牌就宣称整组合法；每个子节点必须从父节点实际执行后的合法集合产生。

节点保存“指定动作后真实状态”和“默认 rollout 后真实状态”两部分。扩展子节点重放前者的完整实际前缀，再选择下一动作；评分用后者。这样三层表示真实的组合执行而非三个互不相干的评分。若某动作在原生效果中生成新牌、抽牌或选择，候选身份和后续合法性以本分支的实际记录为准。

评分只使用原生事实：优先真实 BossVictory；其次尚存活、未发生 Unsupported/错误的节点。固定一席按 HP/下一回合可用防御与剩余药水保守排序，另一席按同一第三形态敌人实际 HP 降低优先；同分用稳定动作/实例标识。不要把动作数、回合数、离散评分或“一阶段 HP 最多”当胜利。相同父状态的 RNG 起点相同，分支消耗不同后不得声称严格配对同随机事件。

## 质量门、停止和后续

出现前缀状态/RNG 不等、观测扰动、未知补丁、身份串线或数据完整性失败，停止依赖该生成链的搜索，先修复生产问题。合法 Death 作为策略结果留在分母；Unsupported 作为未完成分支，不能降格为小分数后宣称其效果已支持。BudgetExceeded 不等于普通失败胜负，实际异常、非法动作、缺数据分别记录。

候选配额用尽即结束这批。不追加“再试一个参数”或自动深一层；没有胜利时交付两个入围轨迹、最远实际阶段、关键死亡原因、裁剪清单和成本。随后可在既有 M1 授权内评估另两个原预登记种子的正常路线，使完整流程验证继续推进；必须保留 DEV_03 未胜利事实，不用换种子覆盖它。不要反复扩大此固定 TestSubject 入口，或因此把策略最优性重新设为 M1 前置条件。

找到实际 BossVictory 后停止新增策略候选，使用同一正常开局 run 继续原生奖励及合法后续生命周期。现有 `NativeMajorContract` 尚不赋予正常路径 RunVictory 权限；必须补实际 Architect/原生任务完成/WinRun 观察与完整数据契约。不得删 guard、直接调用 WinRun 或借尾部夹具关闭完整 run 门。

验收需保存每个候选的源前缀、配置和构建/采集器/输入锁，完整状态/RNG、实际候选及所选实例、动作与子选择关联、原生任务与历史、进程退出/用时/峰值、预算/裁剪/评分依据。搜索轨迹不得冒称 simulator 差分或最优策略。采集器公共变化按影响扩大回归，局部 provider 先做受影响完整前缀及烟测、生产检查器正负控；最终 M1 同构建全量门保持不变。
