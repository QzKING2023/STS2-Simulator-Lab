三、Mod 适配层设计要求

在开始实现前，先提出并记录适配层设计：

- ModSource：输入来源、版本、路径、来源标识；
- ModManifest：Mod 名称、版本、内容类型、依赖和兼容范围；
- ModCard 或等价数据对象；
- ModEvent 或等价事件对象；
- ModEncounter、Reward、Character、Relic 等需要接入的最小对象；
- 内部标准模型；
- 外部 Mod 模型；
- 转换器；
- 校验器；
- 错误类型；
- 兼容性报告。

外部格式不能直接污染核心模拟逻辑。核心模拟只依赖内部标准模型。

四、最小功能范围

本轮先接入一个最小但完整的 Mod fixture，覆盖：

1. 至少一个卡牌或可执行内容；
2. 至少一个事件；
3. 至少一个奖励或资源结果；
4. 至少一个角色/敌人或战斗相关对象；
5. 至少一个明确失败案例；
6. 至少一个缺字段或版本不兼容案例；
7. 至少一个重复加载案例；
8. 至少一个稳定排序/稳定 ID 案例。

目标不是接入全部 Mod 内容，而是证明：

- 能发现；
- 能解析；
- 能校验；
- 能转换；
- 能进入 Simulator Lab；
- 能生成可审计日志；
- 能在错误时准确分类；
- 能重放同一输入。

五、错误处理

错误必须分类，至少包括：

- MissingFile；
- InvalidFormat；
- UnsupportedVersion；
- MissingField；
- InvalidValue；
- DuplicateId；
- DependencyMissing；
- ConversionError；
- DataError；
- Unsupported；
- DeterminismMismatch；
- BudgetExceeded；
- RuntimeFailure。

禁止把所有失败都归类为“读取失败”或“未知错误”。

每类错误必须有：

- 稳定错误码；
- 可读错误信息；
- 相关对象或路径；
- 是否可重试；
- 是否阻止继续运行；
- 建议修复方向。

六、确定性和日志

Mod 适配必须可重复：

- 输入文件顺序稳定；
- ID 生成稳定；
- 映射顺序稳定；
- 相同输入和种子产生相同内部模型；
- 同一失败必须产生相同错误分类；
- 日志中记录 Mod 标识、版本、输入哈希、转换器版本、配置摘要和随机种子；
- 默认只保留一份详细日志和最小元数据；
- 不生成无界临时文件；
- 不把完整 Mod 目录复制到每次运行输出中。
