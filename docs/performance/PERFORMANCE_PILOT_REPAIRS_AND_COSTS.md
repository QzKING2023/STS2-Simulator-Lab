# 职业试点修复与整局成本采样

执行日期：2026-11-04 UTC，2026-11-05 UTC 完成收口。范围：已批准的小样本试点；M1 封存不变。第一批失败及其解释仍保留在 [初始报告](PERFORMANCE_STRATEGY_PILOT_VALIDATION.md)。

## 1. 本轮解决的问题

### Silent：复用原生弃牌选择

上轮停点是 `Survivor` 已派发后，请求 Hand/Discard 选择时被 Lab 桥拒绝。不是原生卡牌不执行，也不能称零派发失败。

本轮在 `NativeSolverChoices` 中复用 CombatSolver 的 `PlanCardChoice`、稳定 token、来源/重复实例索引、StateKey，以及原有原生 `FromHand` 通道，接受 Hand/Discard。牌效仍由原生方法执行。没有实现第二套弃牌逻辑、默认选首项或修改搜索评分。新增 `NativeHandDiscardEvidence` 核对请求/答复/返回的归属与顺序、实际手牌实例、型号/升级/完整 key、重复实例序号和弃牌去向。

实证为两个固定种子的自然首战，每个实际执行两次 Survivor 弃牌。首战全部逐步差分通过。没有独立覆盖升级、多张弃牌、弃牌后自动打出/Sly、任意额外监听器；不能据此宣称整套 Silent 内容支持。

### Necrobinder：根状态固定 Osty 身份

上轮原生与预测执行结果相同，但最后清场后，父分支的 `osty=4/3/9` 变成空值标记 `osty=4294967295/0/0`。原生清场修改了 live `player.Osty`；上游 getter 在分支未召唤过宠物时会回退读取该 live 引用。

新输入 `osty-root-identity.1` 在根捕获时将每个玩家的宠物引用或明确的空值写入现有可分叉字典；后续 getter 只读捕获值，未捕获的 owner 明确失败。继续复用上游 fork、召唤、Creature 状态和 continuation，不改角色或游戏规则。两文件、三处源变换由 `prepare-solver-osty-inputs.py` 复现；旧 `death-amount-sync.1` 输入完整保留，MIT 和归属见 [第三方声明](../../THIRD_PARTY_NOTICES.md)。

两条 Necrobinder 自然首战的全部 14/9 步通过，包含胜利清场后的父分支检查。旧失败样本与修复样本的 14 个实际 continuation 完全相同，末步父分支标记由失败变为通过。另有分支 API 夹具：有/无宠物根、A/B/A 调用上游 SummonOsty、独立生成实例、原状态/RNG/父分支不变。这些夹具不是自然召唤行动，也不证明所有宠物机制或完整 Necrobinder 爬塔。

## 4. 初步成本判断

| 重叠的墙钟计时范围 | DEV01 | EVAL02 |
| --- | ---: | ---: |
| 求解墙钟（含等待） | 95.87秒 | 40.07秒 |
| 原生根动作执行 | 20.30秒 | 8.55秒 |
| 根捕获与原状态检查 | 3.30秒 | 1.59秒 |
| 身份/状态投影 | 7.19秒 | 2.82秒 |
| trace序列化与写入 | 2.26秒 | 0.87秒 |
| 兼容JSON写入 | 3.13秒 | 1.35秒 |

**这些范围有嵌套，不能相加。** 求解墙钟分别约为进程墙钟的63%/61%，是优先深入测量的方向。上游成员归因中，DEV01 的 SmartPotionGradient 约45.83秒，PrimaryBeam 24.80秒，OpeningPowerRouteMember 12.46秒；EVAL02 分别约11.39、17.21、5.97秒。成员工作量、分配量、GC 计数保留在测量文件，不当作互斥 CPU 样本或唯一 GC 暂停总量。

DEV01三幕分别记录111/113/134次求解，展开34,142/27,224/98,367节点，归因搜索耗时13.09/17.07/58.77秒。第三幕占该样本搜索工作的大部分；这是本路径的实测分布，不是所有路径规律。SmartPotionGradient成员归因分配约21.07 GiB、GC暂停约9.70秒；它们提示进一步调查分配与药水搜索的价值，不能解释为21 GiB峰值内存或独占暂停。

首战模式还存在每次观察重写兼容 JSON 的成本；完整流程已有不同的写出策略。不能将首战与整局直接作为优化前后对照。未测精确单节点墙钟、磁盘等待、采样 CPU 堆栈；每幕仅可从 query 归因搜索耗时，缺失项标未知。重放仍重新求解，不能用在线减重放推算搜索耗时。

条件外推：若未来十个 Ironclad 在线样本与这两条成本相近，串行原生执行约11–26分钟，原始产物约1.1–3.3 GiB；不含重放、检查、准备及异常处理。两样本极值不是统计置信区间，也不能代表其他职业、其他配置或长尾种子。本轮未启动100局测试，未声称性能提升。

## 5. 信息边界及后续门

本轮所有搜索和预测继续为 **Oracle**。根状态包含隐藏抽牌顺序、完整 RNG、内部状态和未来预测；成功的 fork 隔离不等于玩家可见信息隔离。[信息边界文档](../architecture/STRATEGY_INFORMATION_BOUNDARY.md)中的白名单观察 DTO、隐藏信息置换不变性和日志/对象引用隔离仍未实现。不能宣称公平玩家策略、真人表现、数学最优或该隔离阶段完成。

建议下一步先对当前修复与成本证据做有界复审，再建立玩家可见观察投影和隔离测试。同时从已存在的上游搜索档位/成员设置中选一个预登记的小型对照，固定信息模式、样本、正确性门和预算后再测。优先调查占比大的搜索工作；不按某个 Boss 改评分，也不立即扩大到100局或所有职业整局。
