# 玩家可见策略整局隔离：下一实现边界

状态：当前仍未认证整局。本文是已授权试点的具体续接，不能替代运行结果。

## 已有能力与复用范围

- `VisibleCombatPolicy` 是仅接收 JSON 的纯策略，禁止未知字段；现有 worker 只引用 Core，无游戏或 Solver 程序集。
- `NativeVisiblePolicyProbe` 已验证投影及父状态/RNG不扰动，`NativeVisibleBattle` 已实际执行原版首战并重放。现有白名单仅为战斗公共子集，未覆盖所有职业资源。
- 原生多幕、奖励、房间、商店、选择和终态执行器继续复用；无需重新实现游戏效果或搜索算法。
- `NativePolicy` 的候选句柄只是局部接口。现有 `PreparedNonCombatRoom`、地图路径评分、奖励偏好、商店筛选、`NativeChoices.Plan` 等仍在宿主内决策；单独替换战斗函数不足以证明整局隔离。

## 必须统一的决策边界

| 决策 | 可见输入及实际映射 | 必须隔离的输入 |
|---|---|---|
| 战斗 | 当前手牌公开属性、可见敌人/意图、资源、合法动作及槽位 | 抽牌顺序、未来意图、游戏 RNG、root/continuation、搜索结果 |
| 地图 | 已显示节点/连线和当前位置，稳定公开顺序 | 未揭示事件/战斗模型、预测奖励、内部随机状态 |
| 奖励 | 当前展示候选、可用操作、公开价格/容量 | 未生成候选、重抽后的结果、Foreseer Oracle 预测 |
| 事件/先古/休息 | 实际展示选项、可用性及公开状态 | 未揭示随机结果；不能使用预选后只暴露一项的伪候选集 |
| 商店 | 当前库存及实际价格、金币、容量和离开选项 | 后续补货结果、未生成库存、内部对象身份 |
| 子选择 | 当前原生请求及展示顺序、数量范围、公开卡属性 | 私有实例 ID、StateKey、宿主预先按隐藏信息排序 |

公开句柄由本次展示位置生成。宿主私下绑定真实对象，验证失效/重复/越界并执行原生命令。诊断日志继续标 Oracle；策略只有序列化公共 DTO。选择回放允许宿主验证完整状态，但不得把回放状态或哈希作为策略输入。

## 建议实施顺序与验收

1. 抽出复用现有纯策略的决策端口，覆盖上述所有入口；在独立模式中禁止 Oracle 策略、Solver 查询和 Foreseer 调用。未知决策类型明确 Unsupported，不能回退到宿主偏好。
2. 从原版 Ironclad/A0/固定种子出发，以简单、确定的公共策略实际执行多节点直到真实 Death 或 RunVictory。早死可验证该次运行的终态，但不能自动覆盖未遇到的房间类型。
3. 用少量显式夹具补必要决策类型；自然与夹具分列。对每种 DTO 做隐藏字段替换、额外字段拒绝、候选顺序/句柄及过期映射控制。秘密替换仅证明固定合法候选向量下的投影不干扰，不声称穷尽所有反事实世界。
4. 同构建重放，逐决策比对公共输入/实际选择、全部原生状态/RNG、终态和清理；要求没有 Solver 查询、没有 Oracle 策略分支。策略与原生的可信数据通道完整后再比较表现。

下一批应先登记资源上限，建议最多 8 次原生执行、30 分钟、2 GiB；接口负控独立计数。不要复用本批剩余额度绕过已登记停止门。测试策略不应为单一 Boss 或失败种子调参。

## 信任及性能口径

这是可信纯策略的数据流隔离，不是能抵御恶意策略读取文件/进程内存的操作系统沙箱。若以后运行不可信第三方策略，需要另立安全边界。

Oracle 与玩家可见策略分别记录输入权限、策略版本和预算。重复同种子用于复现，不是独立统计样本。在线与冻结回放都可能有诊断成本，不能用两者耗时相减推算搜索成本。尚未完成上述整局门之前，不报告公平策略胜率或真人水平。
