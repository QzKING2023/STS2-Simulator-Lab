### 两个实际缺口

1. **Silent 选择桥**：上游已给出 Discard token，Lab `NativeSolverChoices.Resolve` 的旧准入集合没有 Hand/Discard。异常出现在原生 Survivor 已派发后的子选择，已发生前缀完整保留。后续应复用上游 token/候选身份协议补一般弃牌能力，不给 Survivor 另写牌效。
2. **Necrobinder 战后父分支观察**：唯一变化为 `osty=4/3/9` → `osty=4294967295/0/0`。锁定上游 `SimulatedCombatState.CardLifecycle.GetOsty` 在未有分支覆盖时回退 `player.Osty`；真实战斗清理会改变该引用。这是跨原生清理的分支身份/观察契约缺口，不能由此断言搜索主动污染了父状态。需要检查并复用上游捕获机制，令分支身份独立；本轮未修改上游 DLL。

旧运行只写 parentUnchanged=false，进程仍 exit0；生产检查器一直拒绝。现已添加运行时失败传播及 before/after 诊断，最后一次定向执行为 **exit1 / DataError，17确认/17派发，q14**。真实终态观察保留，但没有伪称完整检查通过。

## 4. 成本发现与扩大样本估计

P0只读提取 M1 同构建7条在线路径（1 RunVictory、6 Death）及8条重放，不重新执行：

- 在线墙钟 **49.54–125.97秒**，中位107.97秒；峰值工作集约597–1653MiB。
- 上游记录的累计搜索耗时 **24.88–76.63秒**，约为各进程墙钟的45%–61%。这是搜索报告口径，不是独占CPU占比；原生await、采集及成员时间可能重叠。
- 原始证据 **117–338MiB/局**。条件外推100条相似 Ironclad 路径，串行约 **83–210分钟、11–33GiB**，未含额外重放/检查，也不能外推其他职业、难度或全胜长局。
- P1新加搜索墙钟、root捕获及纯度检查、原生根动作执行、进程CPU计时。首战中初始化约0.80–1.03秒，搜索墙钟0.85–2.53秒，兼容JSON写入0.12–1.28秒；短局固定初始化和重复JSON导出占比更明显。

优先测搜索成员工作量及采集/JSON成本；不要先改评分、无限增大搜索档位或关闭准确性校验。M1使用DOP2/RunToTerminal/16384返回门，本批DOP1/Guarded/4096，不是优化前后对照。重放仍求解，在线减重放无搜索耗时意义。CPU分阶段、分配热点、跨职业完整run成本仍未知。
