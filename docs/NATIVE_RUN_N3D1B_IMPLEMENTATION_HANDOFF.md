# 下一最小子阶段：商店经济、历史与自然进出

状态：4D1 已通过 [最终独立验收](NATIVE_RUN_N3D1_FINAL_REVIEW.md)。本文是已授权 M1/4D 内的直接实施交接；本轮审查没有执行这里的新功能或实验。沿用 Standard，实施 Sol xhigh，之后独立审查。可串行分两次封版，但第二步自然进出仍属于本交接的完成条件。

基线 `7C4D2069013543D1930EFD98BFD14C95C246E9384B527C32A733E43BAC5E03D3`；v0.111.0 / Ironclad / A0 / 一 run 一进程。15 项 Mod 输入和 52 项兼容源码冻结，不开展 Mod 专项或公开 SDK。

## 最小可用交付

1. 在安全宿主中恢复固定原生药水商店价格抖动、对应 Shops RNG 和商店离开历史语义，执行限定夹具并证明安全/重放/记录。
2. 新增正常开局的自然路径：Neow → 原生战斗/奖励 → 合法地图 Shop → 实际原生交易或取消 → 合法下一节点的首个决策。同一 Run，不注入金币、牌组、库存，不用 EnterRoomDebug。必须至少有一条实际交易成功的自然路径；因早死、缺钱、未知效果停下的样本如实保留，不能改写成成功。

这里不一次纳入全部遗物、补货和复杂奖励。自然遇到当前不支持的原生分支，保留真实前缀并明确 Unsupported，再按剩余 4D 闭环；不能静默跳过效果。完成仍不代表完整 4D/M1。

## A：先闭合价格、RNG、历史语义

1. 只读核验精确游戏方法及异步 MoveNext、TestMode 分支、地图历史创建和所有保存/平台入口。给出方法、程序集、IL/签名和预期匹配数清单。保持全局 TestMode、安全保存拦截、Steam 禁用。
2. 建议优先评估固定方法中仅针对 TestMode 判定的窄转接：例如在特定 CalcCost/Exit 中改用正常业务分支，保留其余原生 IL。若采用 transpiler，要求精确原始方法匹配、预期唯一锚点、未知补丁拒绝、注册签名纳入宿主身份、版本不符拒绝；不能笼统替换所有 TestMode 调用。该方案尚未实施或证明安全，实施者应据实际调用链选择更窄的既有入口。
3. 原生价格/历史 profile 必须在证据和冻结配置中显式标记。旧 TestMode 夹具保留为旧语义基准；不能将不同 profile 的价格、RNG 或历史混为同一承诺。
4. 先跑限定 API 夹具：真实生成库存、购牌/购药/移除/取消、真实原生退出历史。记录实际价格、付款、库存、物品和历史；不假设整个库存生成只增加三次 RNG，整个创建过程还包含抽取等消耗。
5. 观测开启与最小/关闭对照、固定重放必须比较完整 RNG 和相关状态。检查历史操作没有引入保存/网络调用；若原生历史链涉及新敏感入口，先完成可审计隔离再执行，不全局取消保护。

价格验证除运行前后取值外，应有独立契约和至少一个固定已观测输入输出锚点，避免用同一运行时 Cost 自我推导期望。可另做受控 RNG 夹具，但须标明 fixture，不将它当自然分布/全种子覆盖。原生算法仍是执行主体，独立契约只是证据检查。

## B：自然商店会话与合法离开

1. 在 `NativeMerchant` 里复用原生购买、移除桥和实例身份；绑定当前 Run/room/inventory/session，每次操作持有对应票据。保留原生 Hook 调用和父子选择。当前卡/药取得替换、补货尚不支持，结果必须明确停点。
2. 在房间控制器接入新自然场景，不改变旧 DEV 样本。预登记有限种子列表、地图优先规则、交易选择规则、预算与完成判定；允许根据当前公开合法信息选可负担商品，不额外注入资源。记录失败分母；探索找到的路线与预登记验证 cohort 分开。
3. Travel 开始绑定当前完整确认状态；原生退出历史在真实业务区间变化；Travel 返回绑定实际新房间、地图和历史，之后才确认新会话。原商店 Closed 守卫仅用于拒绝旧操作，不能替代原生退栈。
4. 自然分支至少实际购买一次卡或药并进入后续合法节点；另保留取消/不购买离开的证据，可用有限专用夹具补取消分支，不冒充同一自然路线。取得卡/药必须是原生实际实例；选中奖励/商品不要求强制摆入首手。
5. 当前阶段的下一决策可以是合法房间动作；若下一节点为战斗则至少执行一个合法 Play。继续推进到何处按预登记预算，不为满足商店验收顺带展开整个跨幕控制器。

## 生命周期与数据契约先行

| 区间 | 必须采集/验证 |
| --- | --- |
| 自然房间到达 → 会话打开 | 当前地图/房间/库存实际实例、来源 natural、执行方式 live 或 frozen-replay 独立；请求与会话唯一 |
| dispatch → operation open | 当前动作/context/session 和完整不可变快照一致；过期会话零派发拒绝 |
| 购买/移除与嵌套选择 | 必需、唯一、顺序和具体实例；付款、库存/牌组/药槽差异；取消与拒收不得伪报取得 |
| SetUsed → Hook 进入/完成 → return | 当前 profile 无业务变化时保持已验收完整比较；有真实 Hook 变化时增加显式业务区间和结果契约，不删除比较 |
| return → confirmed → room-ready | 完整静止状态绑定，实际已发生失败前缀与未确认根动作保留 |
| Travel dispatch → exit start | 完整静止状态一致；退出执行只能一次、归属当前旧房间和动作 |
| 原生 Exit → Travel return | 原生历史/房间栈/地图的真实变化可见；具体旧库存和历史条目关联；不要求业务前后全状态相等 |
| 新房间确认/旧票据失效 | 绑定真实新 room/map/session；旧库存和选择票据不可继续使用 |

历史原始事件与汇总分开，记录已购与未购的真实对象/型号/升级/价格及来源。原生历史若只保存型号等较弱字段，不得声称原生提供了实例 ID；Lab 关联记录应标明其来源并绑定之前的库存。验证是否有游戏规则消费这些历史字段，而不只把它们当报表。公开决策输入保持玩家可见标签，oracle 全状态用于验证不能误称公平策略。

## 最小验收矩阵

- **版本/安全**：错误方法或补丁签名拒绝；MemorySaveStore、ShouldSave=false、SaveProgress/replay/Steam/网络护栏保持；全局 TestMode 未关闭。
- **价格/RNG**：新 profile 原生抖动分支实际执行；固定 seed 重复和完整 RNG 重放一致；观察模式不改变库存、价格、付款、RNG。与旧 profile 的差异明确分列。
- **历史**：真实正常/取消/失败交易后离开；已购与未购条目按原生行为记录；历史存在且归属正确、只写一次，遗漏/重复/错配/错序被生产检查器拒绝。
- **自然路径**：同一 Run 正常开局到实际 Shop，真实交易后合法 Travel 至后续首决策；没有 GainGold/EnterRoomDebug/手工库存或历史准备；失败样本保留。
- **契约负控**：移除整组选择、重复结果、挪用旧 session、错实例/付款、两个中间快照共同漂移、静止边界未知字段、伪 Closed/退栈、缺历史及退出重复；对应合法取消、真实业务变化、结构等价副本通过。
- **失败**：过期动作、原生异常和预算停止保留确认前缀，不被最外层 exit0 掩盖；原生失败和 reader 检测到预期损坏分开计数。
- **最终回归**：冻结实际 dirty 源码/输出/配置后，串行执行全部适用 1–4D1B 矩阵、原253商店控制与历史包、自然 skip/take、4A终态、DEV01/02/03和完整 RNG；Core98、15输入、52兼容源码核对。若最终再改代码，不能继续沿用旧二进制结论。

可先封版 A 的夹具和语义护栏，再实施 B；提交报告须明确两者状态，不能 A 通过便把自然商店打勾。不要为了复跑不断扩张本轮无关 schema 或公开扩展体系。
