# M2 uses an append-only inventory and risk-based content evidence

M2 will freeze a content inventory for each exact game version, snapshot, configuration, and runtime condition, but any newly observed registration identity must be appended and revalidated before a prior compatibility result remains valid. Every content unit requires a fresh-process lifecycle proof; repeat, replay, or dedicated probes are added for stateful, random, cross-room, or interaction-sensitive behavior. Flow evidence remains a fixed `primary/repeat/replay/failure` contract at the Mod level.

## Consequences

- Static discovery can seed the inventory but cannot make a content unit `Covered` by itself.
- New runtime identities cannot be hidden by an earlier report or silently folded into an existing unit.
- Evidence effort follows semantic risk while preserving a fixed four-path run contract.
